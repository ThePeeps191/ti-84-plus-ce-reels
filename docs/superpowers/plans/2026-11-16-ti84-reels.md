# TI-84 Plus CE Reels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> Scope note: the user asked for end-to-end delivery without review gates, so this plan lists exact interfaces and tests per task rather than full code listings.

**Goal:** Stream the user's live Instagram Reels to a USB-tethered TI-84 Plus CE, controlled from the calculator keypad.

**Architecture:** The Node host drives a dedicated Chrome over CDP, grabs the current `<video>` into a 136×240 canvas, quantizes it to a 12/240-color adaptive palette and streams BLIT messages over USB CDC serial. The calculator C program (REELS.8xp, run through arTIfiCE) is a dumb framebuffer plus keypad.

**Tech Stack:** Node 24 (playwright-core, serialport, usb), CE C toolchain v15.0 (graphx, keypadc, srldrvce, usbdrvce), Chrome 157.

**Spec:** `docs/superpowers/specs/2026-11-16-ti84-reels-design.md`

## Global Constraints

- Wire frame: `0xA5, type u8, len u24 LE, payload`; message types and payloads exactly as in the spec table.
- Screen layout: left panel x 0–91, video x 92–227 (136×240), right panel x 228–319.
- Palette: 4bpp has UI 0–3 and video 4–15; 8bpp has UI 0–15 and video 16–255. Colors are 1555 (`gfx_RGBTo1555`).
- 4bpp packing: left pixel in the low nibble (to be confirmed on hardware with DUMP in Task 4).
- Calculator USB: CDC `16C0:05E1`. DUSB (OS link): `0451:E008` on WinUSB.
- Chrome profile: `%LOCALAPPDATA%\ti84-reels\chrome-profile`, CDP port 9333.
- Toolchain location for builds: env `CEDEV`, default `%LOCALAPPDATA%CEdev` (README documents the install).

### Task 1: Host scaffold + protocol

**Files:** Create `host/package.json`, `host/src/protocol.js`, `host/test/protocol.test.js`, `.gitignore`.

**Produces:**
- `encode(type:number, payload:Buffer=Buffer.alloc(0)) → Buffer`
- `class Decoder { push(chunk:Buffer) → Array<{type:number, payload:Buffer}> }` (streaming, resyncs on a bad magic byte)
- `T = { HELLO:0x01, MODE:0x10, BLIT:0x12, DUMP:0x20, QUIT:0x30, C_HELLO:0x81, ACK:0x82, KEY:0x83, BYE:0x84, C_DUMP:0x85 }`
- `blitPayload({x,y,w,h,palStart,palette:Uint16Array|number[],pixels:Buffer}) → Buffer`
- `KEYS = { UP:1, DOWN:2, ENTER:3, SECOND:4, ALPHA:5 }`

- [ ] Tests: round-trip encode→decode, a message split across 3 chunks, two messages in one chunk, garbage before the magic byte, a 70 KB payload (u24 length), blitPayload layout bytes.
- [ ] Implement; `node --test` passes; commit.

### Task 2: Pixel pipeline (quantize + pack)

**Files:** Create `host/src/quantize.js`, `host/src/pack.js`, `host/test/pipeline.test.js`.

**Produces:**
- `rgbTo1555(r,g,b) → number` (identical to graphx `gfx_RGBTo1555`: `((r>>3)<<10)|((g>>3)<<5)|(b>>3)`)
- `quantize(rgba:Uint8Array|Buffer, w, h, nColors, prevPalette?) → { palette: Array<[r,g,b]>, indices: Uint8Array }` (median cut + 2 k-means passes seeded from prevPalette when given; 4×4 Bayer ordered dithering)
- `pack(indices:Uint8Array, w, h, bpp:4|8, offset:number) → Buffer` (adds `offset` to every index; at 4bpp the left pixel goes in the low nibble)

- [ ] Tests: index range < nColors, palette length ≤ nColors, solid-color image → 1 effective color, deterministic output, 4bpp pack of `[1,2,3,4]` with offset 4 → `[0x65,0x87]`, 8bpp pack with offset 16, rgbTo1555 of white/black/pure red.
- [ ] Implement; tests pass; commit.

### Task 3: Calculator program REELS + deploy tooling

**Files:** Create `calc/makefile`, `calc/icon.png`, `calc/src/{main.c,link.c,link.h,proto.c,proto.h,display.c,display.h}`, `tools/dusb.js`, `tools/deploy.js`, `tools/package.json` (shares host deps via `host/node_modules` resolution; tools are run as `node tools/x.js` from the repo root with `NODE_PATH=host/node_modules`, or simply live under `host/tools/`). Decision: put the tools in `host/tools/` so they share `host/package.json`.

**Produces (calc behaviour):** implements the spec protocol. Status screen "TI-84 REELS / waiting for laptop… / [clear] quit". The receive buffer is `lcd_Ram + 76800`. BLIT is applied as palette then rows. MODE switches bpp via `lcd_Control = (lcd_Control & ~0xE) | (bpp==4 ? 4 : 6)` and clears the screen. DUMP streams back `C_DUMP`. Key edges send KEY. [clear] sends BYE, `usb_Cleanup`, `gfx_End`.

**Produces (tools):** `host/tools/dusb.js` (the spike client, unchanged API: `Dusb.open/modeSet/params/screenshot/key/sendVar/dirList/close`, `savePng565`, `png`); `host/tools/deploy.js [--build] [--with-clibs]`, which waits out the shell (error 0x36), sends `calc/bin/REELS.8xp`, then remote-launches `prgmA`.

- [ ] Write the calc sources; build with `make` (CEDEV/bin on PATH) until clean.
- [ ] Deploy to the calculator; the user launches REELS; verify that the status screen appears (USB disappears from DUSB, COM port appears).
- [ ] Commit.

### Task 4: Calc link (host serial) + hardware verification

**Files:** Create `host/src/calc-link.js`, `host/tools/testpattern.js`, `host/tools/dump.js`.

**Consumes:** protocol.js, pack.js.
**Produces:** `class CalcLink extends EventEmitter` with `start()`, `stop()`, `async setMode(bpp)`, `async blit({x,y,w,h,palStart,palette,pixels})` (resolves when the ACK arrives; at most 2 in flight), `async dump() → {bpp, palette:Uint16Array, vram:Buffer}`, `quit()`, a `connected` property, and events `connect({bpp})`, `disconnect`, `key(code)`, `bye`.

- [ ] testpattern.js: send MODE 4 with colored bars plus pixel-exact text, then DUMP → PNG to verify the write path. The user confirms visually that the text is crisp; garbled text means the nibble order is swapped. Repeat at 8bpp. Measure blit fps for the 136×240 region at 4bpp and 8bpp.
- [ ] Fix the nibble order in pack.js if the DUMP disagrees; commit.
